# Оплата тарифов — Точка.API

## Что добавлено

- На карточках индивидуальных и групповых занятий есть кнопка «Выбрать тариф».
- 16 тарифов из приложенного PDF перенесены на сайт: групповые/индивидуальные, старший тренер/тренер, разовые занятия и абонементы.
- Стоимость и тариф проверяются на сервере — сайт не принимает сумму от браузера.
- При настроенном API сайт создаёт новую платёжную ссылку через Точка.API и переводит клиента на страницу банка.
- После возврата статус не считается успешным только потому, что клиент вернулся на сайт. Он меняется на «Оплачено» после валидного подписанного webhook от Точки.
- Пока API не настроен, конкретный тариф открывает существующую QR/СБП-ссылку, встроенную в PDF. Этот режим нужен только как временный переход: сайт не сможет сам подтвердить оплату по старой внешней ссылке.
- Есть два варианта запроса: без чека и с чеком. Вариант с чеком включается только после заполнения реквизитов продавца и согласования налоговых параметров.

## Что обязательно получить у заказчика

1. Подтверждение, что интернет-эквайринг Точки подключён и торговая точка активна. В `Get Retailers` должны быть статус `REG` и `isActive: true`.
2. JWT-токен интернет-банка с разрешением `MakeAcquiringOperation` для создания платёжных ссылок.
3. `customerCode` бизнеса (9 цифр). Если у бизнеса несколько торговых точек, также `merchantId` (15 цифр) нужной точки.
4. Внешний домен сайта на HTTPS. Redirect URL и webhook на localhost не подойдут для боевой интеграции.
5. Подтверждение по онлайн-кассе/54-ФЗ: нужен ли чек, какая система налогообложения, ставка НДС, официальное наименование продавца, ИНН и телефон поставщика.

## Подключение

1. Сделайте копию `payment.local.example.php` и назовите её `payment.local.php` рядом с `payments.php`.
2. Внесите реальный `api_token`, `customer_code`, при необходимости `merchant_id`, и `site_url` вида `https://домен-сайта.ru` без слеша в конце. Не добавляйте токен в `payments.js`, HTML или клиентские переменные.
3. По умолчанию включены `sbp` и `card`. Добавляйте `tinkoff` (T-Pay) или `dolyame` только если они доступны для этой торговой точки в Точке.
4. Для электронной фискализации после подтверждения бухгалтера заполните `supplier_name`, `supplier_tax_code`, `supplier_phone`, `tax_system_code`, `vat_type` и поставьте `receipt_enabled` в `true`. При этом клиент введёт имя и email, а backend использует метод `Create Payment Operation With Receipt`. Значения в sample-файле — примеры, не налоговая рекомендация.
5. В интернет-банке или настройках API зарегистрируйте webhook события `acquiringInternetPayment` на адрес:

   `https://домен-сайта.ru/payment-webhook.php`

   Подключение webhook требует HTTPS на стандартном порту 443. Сервер проверяет подпись JWT по публичному ключу Точки; ключ загружается с `https://enter.tochka.com/doc/openapi/static/keys/public` и кэшируется в `storage/`.
6. Проверьте на тестовом тарифе: создание ссылки → оплата в тестовой среде банка → возврат на `payment-result.php` → webhook → статус «Оплата подтверждена».
7. Перед боевым включением выполните тестовый платёж небольшой суммы, проверьте чек/кассу и соответствие активным способам оплаты.

## Технические детали

- `payments.php?action=tariffs` — отдаёт список тарифов.
- `payments.php?action=create` — принимает `tariffId`, сам вычисляет сумму и запрашивает платёжную ссылку у Точки.
- `payments.php?action=status&paymentLinkId=BELKA-...` — возвращает статус сохранённого заказа.
- `payment-webhook.php` — принимает JWT, проверяет подпись RS256, сверяет идентификаторы и сумму заказа и помечает только статус `APPROVED` как оплаченный.
- `payment-result.php` — страница возврата из банка; URL-параметр сам по себе не означает успех оплаты.
- Заказы/статусы сохраняются в `storage/payments.json`; папка `storage` уже закрыта от прямого доступа через `.htaccess`.

## Важные ограничения до запуска

- В архиве нет реального токена, `customerCode`, `merchantId` и налоговых реквизитов заказчика, поэтому проверить создание реального платежа невозможно. Не включайте заглушечные данные из примера.
- По умолчанию выбран метод `Create Payment Operation` без фискализации. Если бизнес обязан выдавать кассовые чеки, сначала настройте вариант `Create Payment Operation With Receipt` и проверьте его с бухгалтером/кассовым сервисом.
- Старые ссылки, извлечённые из PDF, являются резервными внешними ссылками на оплату. По ним не приходят вебхуки в этот сайт, поэтому нельзя автоматически подтвердить оплату внутри CMS.
- Эта доработка реализует оплату выбранного тарифа. Она не заменяет отдельную интеграцию расписания/бронирования YCLIENTS и не подтверждает запись на конкретное время.
